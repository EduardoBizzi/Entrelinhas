## Decisões de implementação

1. O registro principal é um **livro com atividade de leitura agendada**. Seu `eventAt` alimenta o calendário. O status e as páginas são campos do tema biblioteca; não são registros decorativos.
2. O SQLite guarda somente alterações pendentes, incluindo tombstones. Registros já enviados são removidos dessa tabela após ACK. O cache persistente do SDK Firestore permite consultar a última cópia da nuvem offline. Assim, a exigência de limpeza não é ignorada para manter uma segunda tabela de livros sincronizados no SQLite.
3. Wi-Fi/rede móvel não comprova acesso ao servidor. Erros e timeouts preservam a fila. O rótulo de sincronizado depende de confirmação, não apenas do `connectivity_plus`.
4. Fotos são locais, opção permitida pelo enunciado. Capa da Open Library é uma URL pública, enquanto foto escolhida pelo usuário é arquivo local. Nenhum caminho de arquivo é tratado como URL de nuvem.
5. O UUID identifica o documento. `changeId` identifica a versão local enviada; se ocorrer uma nova edição antes do ACK, ela não é apagada. Entre aparelhos, a política é a última gravação aceita pelo Firestore; não há mesclagem campo a campo.
